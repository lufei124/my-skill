# Claude Agent SDK 运行层设计

本文件是本 Skill 的方案约束与接入检查表，不是可运行代码。除明确标注的官方能力外，以下分工、配置结构、迁移步骤和测试要求均为本 Skill 的设计建议。出处见 [sources.md](sources.md) 的 S16–S24。

## 1. 先确定约束，不重新做无约束选型

默认结论必须是：**Agent 运行框架采用 Claude Agent SDK；模型服务商按项目需求单独配置。**

只有用户明确排除 SDK，才设计替代框架，并记录原话及来源。模型偏好、现有 OpenAI-compatible 客户端、部署困难、旧方案结论、参考仓库支持其他运行方式，都不能自动构成豁免。若受项目硬限制阻塞，交付保留 SDK 目标的适配方案与阻塞项，不伪称可部署，也不绕开项目限制。

Anthropic Client SDK、Claude Code CLI 和 Claude Agent SDK 不是可互换的名称；普通 API 客户端加自研循环不满足本 Skill 的要求。SDK 提供 Python/TypeScript 接口和 Agent 循环，不仅用于终端交互。[S16]

## 2. 最小集成方式

| 当前项目 | 建议接入 | 保留内容 |
|---|---|---|
| Node.js / JavaScript / TypeScript 后端 | `@anthropic-ai/claude-agent-sdk`；按现有模块制式设计薄适配 | 路由、鉴权、服务、数据库、前端 |
| Python 后端 | `claude-agent-sdk`；导入名 `claude_agent_sdk` | 现有 API、服务、数据层和队列 |
| 其他业务语言或纯前端项目 | 在合适的后端/worker 增设薄 TypeScript 或 Python SDK 承载层 | 不为 SDK 重写整个业务项目；密钥不放前端 |

包名及基本入口依据官方快速入门；具体依赖、运行环境和打包方式必须按项目锁定版本核对。SDK 涉及 Claude Code 运行进程与本地状态，不能把它当作任何环境都能直接运行的纯 HTTP 客户端。[S17、S21]

方案要写清运行位置、依赖/二进制可用性、工作目录、资源上限、并发容量、取消与进程清理。不得默认 serverless、浏览器或现有容器已经满足条件；不写未经测量的内存和并发承诺。

## 3. SDK 与项目的责任边界

| 能力 | 设计归属 |
|---|---|
| 模型—工具多轮循环、上下文管理 | 交给 SDK；不另建平行 Agent 主循环 |
| 自定义业务工具 | 通过 SDK 自定义工具/MCP 接入，handler 调现有 Backend/领域服务 |
| 会话连续性 | 使用 SDK 会话机制；宿主管理用户/项目与会话的映射、存储、恢复、删除和隔离 |
| 前端流式消息 | 宿主把 SDK 事件适配为现有 SSE/WebSocket 协议；不自己解析模型文本来调度下一轮 |
| 权限、可信审批、幂等、审计和限额 | 宿主与 Backend 强制执行；SDK 权限控制只是其中一层 |
| 定时、持久任务和业务写入结果 | 复用项目任务引擎/状态机，不假定 SDK 会话等于持久任务队列 |
| 长期偏好记忆 | 仅有明确需求时建设；不等同于 SDK 会话历史 |
| 子 Agent | 仅按需使用 SDK 能力，配工具/上下文/预算边界；不是默认必须建设 |

SDK 的循环、会话、子 Agent 能力见 S16；自定义工具见 S18。表中的业务分工是本 Skill 的建议，不是 SDK 自动提供的完整生产能力。

正常的 `for await` / `async for` 消费 SDK 消息不是自研循环。禁止的是：再次调用普通模型 API、自己挑工具/回传结果/推进轮次，形成绕开 SDK 的第二个 Agent 引擎。工具 handler 内执行确定性业务流程不受此限制。

## 4. 业务工具与安全边界

建议主链路：

```text
现有用户入口 → 可信身份与配置解析 → Claude Agent SDK
                                         ↓
                               自定义工具 / MCP
                                         ↓
                             业务执行门 → 原有服务
```

官方自定义工具可通过进程内 MCP 服务注册，不必为每个工具新建独立服务；TypeScript 有 `tool`、`createSdkMcpServer`，Python 有 `tool`、`create_sdk_mcp_server`。[S18]

- 先枚举模型实际可见的工具，再设计自动批准和拒绝规则。`allowedTools` 是自动批准列表，不是“除此以外的工具全部不存在”的保证；按目标版本配置工具集和权限。[S18、S19]
- 业务助手默认不开放与任务无关的 Shell、文件读写、任意网络、数据库直连或递归委托。只读业务工具不意味着宿主文件系统也可任意读取。
- 工具定义、Skills、设置和 MCP 服务只来自受控来源；工作目录和挂载范围显式设计，不默认继承开发者本机的全部插件、凭证和配置。
- 身份/租户由可信宿主绑定；每次调用和会话恢复都复检资源权限。SDK 自动允许工具执行，不等于用户拥有该业务权限。
- 审批绑定变更内容、版本、批准者与期限；执行前由 Backend 复检。不要用全局自动批准代替业务审批，后台任务和子 Agent 也不能绕过此门。
- 工具错误、截断、空值和超时必须结构化返回；副作用不确定时按操作 ID 核验，禁止盲目重试。

## 5. 模型可配置，但兼容性必须单独验证

只配置用户或项目需要的供应商，不因本文件举例而给所有项目强塞三家。

| 服务商示例 | 设计处理 | 当前证据边界 |
|---|---|---|
| DeepSeek | 核对其 Anthropic 兼容接口、目标模型和限制 | 官方有兼容文档；不代表本项目 SDK 全链路已通过 [S22] |
| 千问 / 阿里云百炼 | 按地域、业务空间、模型和鉴权核对兼容端点 | 官方有 Messages 兼容文档；不混用普通 OpenAI-compatible 地址 [S23] |
| 火山方舟 | 核对具体平台产品/套餐、目标模型或接入点、协议和允许用途 | 附带来源仅核到官方索引摘要，不能由此认定全部方舟接口兼容 [S24] |

不存在适用的直连接口时，可以评估提供 Anthropic Messages 格式的网关。网关也要验证协议与模型行为，不能承诺“只改 URL 就完全兼容”。官方网关文档说明的协议要求，不等于 Anthropic 对所有第三方模型的兼容保证。[S20]

配置契约建议如下；这是**项目配置草案，不是 SDK 的原生配置 schema**：

```yaml
agentRuntime: claude-agent-sdk
providerProfile:
  provider: <项目所需供应商>
  baseUrl: <已核对的兼容端点或网关地址>
  model: <已核对的模型或接入点标识>
  apiKeyRef: <服务端密钥引用，不是密钥明文>
  compatibilityStatus: untested
```

接入方案必须说明：

1. 服务端把配置映射到目标 SDK 版本支持的模型、认证和运行环境选项；参数名/环境变量逐项核验，不发明通用 `baseUrl` 原生参数。
2. 配置按会话/运行实例隔离；禁止通过每请求修改共享 `process.env` / `os.environ` 切换供应商。清理互相冲突的继承配置，密钥不进入 Prompt、工具结果、前端或日志。
3. 主模型、辅助调用及子 Agent（若采用）的有效模型路由均需检查，避免遗漏后回到未经批准的模型/账号。运行中不静默跨供应商；变更配置的会话恢复策略要明确。
4. 供应商无兼容能力或验证失败时，停用该配置或受影响功能、明确阻塞。模型降级只可使用事先批准且验证过的配置；不把切回自研 Agent 引擎当自动降级。
5. 用量字段、费用计算、缓存、思考和结构化输出按供应商能力处理；缺少计费证据时记录实际可得用量，不把 Claude 价格估计当第三方账单。
6. 核对服务商产品/套餐的可用范围与生产使用条件；工具接入示例不自动证明该账号可用于面向用户的生产服务。

## 6. 实施顺序与验证门

本 Skill 默认只生成方案与测试设计，不自动安装 SDK、运行付费请求或修改项目依赖。

先规划最小 SDK 闭环验证，再扩展全量工具：

| 检查 | 最低通过条件 |
|---|---|
| 真实运行链路 | 实际进入 SDK 主循环；模型选择与返回工具调用由 SDK 推进，不是自研循环改名 |
| 认证与路由 | 请求到达预期端点/模型；错误密钥、无效模型、不可用配置有清楚错误；日志脱敏 |
| 多轮工具调用 | 一次任务内完成至少两个有依赖的调用，调用 ID/结果关联正确，最终结论可追溯 |
| 流式、失败和取消 | 流式正常结束；参数错误、工具失败、超时、断连或取消可停止并释放资源 |
| 工具/权限隔离 | 未授权工具和无关内置工具不能执行；用户/租户、会话、凭证不串用 |
| 会话恢复（如采用） | 真实恢复上下文而非仅显示历史文本；复检用户/项目归属及当前权限 |
| 预算 | 轮次、时间、工具结果大小和并发均受限；供应商成本估计不可靠时仍有硬停止条件 |
| 可选能力 | 子 Agent、结构化输出、思考、多模态等按实际选用项验证，不默认全支持 |

多供应商分别填 `untested / passed / partial / failed`，记录测试版本、端点/模型、范围、证据与限制。厂商文档声明不是 `passed`；仅聊天成功也不是 Agent 闭环通过。最小授权、审计、超时与预算跟随第一闭环落地，不全部推迟到生产优化阶段。

## 7. 生成方案必须出现的结论

- **运行框架**：Claude Agent SDK；如有明确豁免，写出用户原话与替代方案。
- **接入**：SDK 语言/包、可确认版本、运行位置、工具注册、会话与事件适配。
- **保留与改造**：保留业务服务；原自研循环如何迁移，不并行新建第二套主引擎。
- **模型**：配置边界、兼容证据与未测试项；不把非 Claude 模型需求解释成禁用 SDK。
- **上线门槛**：最小闭环、权限隔离与预算测试，以及真实阻塞项。

禁止只有一句“使用 SDK”，后面的架构、流程、文件和阶段仍全部按自研循环展开。
