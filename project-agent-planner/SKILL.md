# 当前项目 Agent 方案生成器

基于当前项目的真实业务与技术条件，设计最小、可落地的 Agent 方案。参考 `anthropics/commerce-agents` 的设计模式，而不是把当前项目改成电商，或强制依赖其代码包。

## 运行框架硬约束

**只要方案需要 Agent，默认必须使用 Claude Agent SDK；只有用户明确要求不用，才可采用其他运行框架。**这是本 Skill 的方案约束，不是原仓库的强制要求。

- 未收到明确豁免时，不把 SDK 写成“可选”“后续评估”或“迁移 Claude 后再考虑”，不推荐自研 Agent 循环作为主路线或自动降级路线。
- 明确豁免包括用户直接说“不用 Claude Agent SDK”，或明确要求以另一框架/自研循环替代它。方案必须记录用户原话及来源；旧方案自行写出的“不引入 SDK”不算用户授权。
- “保留现有技术栈”“继续用 DeepSeek、千问、火山方舟”“不要用 Claude 模型”“控制成本”都不是 SDK 豁免。模型选择与 Agent 运行框架分别设计。
- 已有服务和普通模型调用可保留；拟建设或改造的 Agent 主循环必须真正由 SDK 承担。仅安装 SDK，或用普通 Anthropic API 客户端包装自研循环，不算采用 Claude Agent SDK。
- 环境限制、版本冲突或供应商兼容性问题应写成适配项/阻塞项，不擅自换框架，不宣称已经兼容。与必须遵守的项目规则冲突时标明冲突，不越过规则或修改规则文件。
- 无需 Agent 的场景仍用确定性工作流；本约束不意味着强行引入 Agent、全部替换现有 AI 能力或建设多 Agent。

## 工作边界

- 默认只调研、设计和生成方案文档，不修改业务代码、依赖、数据库、线上配置或项目指令文件，不自动部署。
- 目标项目是用户指定路径或当前工作区；本 Skill 目录和 commerce-agents 参考仓库不是默认目标项目。
- 保留现有业务语言、框架、服务、权限和交互；为 Claude Agent SDK 设计最小接入层。已有 Agent 做增量迁移评审，不默认推倒重写整个项目。
- 先查项目再提问；可从文件确定的信息不重复询问。缺少信息时标为待确认并给保守方案，不虚构现有接口，也不因非关键缺口停止交付。
- 区分项目事实、文档声明、推断和设计建议；源码行为与需求不一致时并列说明，不静默替换。

## 1. 建立项目事实

先读宿主适用的项目规则，再定向检查：

1. README、依赖清单、目录结构、产品/架构文档：产品目标、用户、技术栈、运行位置。
2. 与候选任务相关的页面、路由、服务、数据模型：真实业务实体和操作链路。
3. 鉴权、权限、会话、任务队列、审计、测试：哪些能力已有，哪些只是界面或样例。
4. 已有模型调用、工具注册、提示词、Skills、Agent 循环：可复用部分和实际短板。

只读取相关文件，跳过依赖目录、构建产物和大体积资源。不要读取或输出真实密钥、`.env` 值、私钥或生产用户数据；接口结构可从脱敏样例和类型定义确认。不要为调研执行仓库脚本、安装依赖或调用生产写接口。

记录关键结论的 `文件路径:行号` 或 `文件路径#符号`；没有读取过的路径不能作证据。只有概念或 PRD 时，产出“概念方案”，将所有建议路径和接口标为拟新增。

## 2. 选择场景与 Agent 边界

先列用户要完成的任务，再决定是否需要 Agent。

- 固定、可穷举的步骤：优先普通功能或确定性工作流。
- 需要理解开放意图、组合工具或持续澄清：考虑一个主 Agent。
- 只是不同任务流程：优先拆成按需加载的 Skills，不是一流程一个 Agent。
- 用户群、权限或数据隔离不同：才考虑独立角色；共享基础设施不代表共享权限或会话。
- 独立复杂分析且确有隔离价值：考虑受限 Delegate；后台耗时任务优先复用任务队列，不自动等同于子 Agent。

为候选场景写清：服务对象、触发入口、输入、期望结果、现有依赖、风险和优先级。推荐能形成闭环的最小 MVP，并说明暂不做什么。没有适合的 Agent 场景时直接说明，不硬凑。

## 3. 映射参考模式

先读 [commerce-patterns.md](references/commerce-patterns.md) 的“使用边界”和“模式选择表”；再按项目需要读取具体条目。原始出处见 [sources.md](references/sources.md)。

逐项标注“采用 / 复用已有 / 延后 / 不适用”，并给项目理由：

- 一个会话由一个主 Agent 负责；角色和只读委托按需拆分。
- 角色契约、Backend 接口、统一执行器与运行时适配分离。
- 规则按 Tool Description / 静态 Prompt / 按需 Skill 分层。
- 外部内容隔离；事实回答先读取可信来源；写操作在代码层校验。
- UI 的事实字段由服务端填充；会话状态与可选长期记忆分开。
- 对不存在的能力关闭工具和相关流程；暂未接通的能力不能宣称可用。

### 落实 Claude Agent SDK 接入

只要推荐 Agent，就读取 [sdk-runtime.md](references/sdk-runtime.md)，按上述硬约束确定运行层：

- 选择适合现有部署的 TypeScript 或 Python SDK 接入方式，写清包名、可确认的版本、宿主入口、工具注册、会话和流式事件衔接；其他业务语言可通过薄服务接入，不迁移整个项目。
- SDK 承担 Agent 循环与上下文管理；项目继续承担身份/权限、业务工具、可信审批、任务持久化、审计和预算。消费 SDK 事件流不等于自研循环。
- 现有工具优先经 SDK 自定义工具/MCP 接回原服务；逐项说明复用、改造和新增。默认关闭无关的 Shell、文件写入与任意网络访问能力。
- 需要多供应商时，保留配置入口，分别核验目标服务的 Anthropic 兼容接口或网关；不能把 OpenAI-compatible 地址直接当作兼容证明，也不能把“可配置”写成“已实测可用”。
- 未明确豁免时只规划 SDK 主路线；不默认建设三套运行时、向量库、长期记忆平台或多 Agent 系统。任何具体 SDK/API 参数都需核对目标版本，无法核对则注明。

## 4. 设计工具与关键链路

按需分为读取、呈现、写入/暂存、委托工具；不存在的类别不强行补齐。数量由 MVP 决定，不设机械下限。

每个 MVP 工具明确：用途、关键输入/输出、Backend 方法、真实数据源、已有实现路径或“拟新增”、接通状态、调用者权限、前置校验和失败行为。至少展开一个关键读工具，以及一个写工具（若有）的契约。

后端接通状态使用：`live / sandbox / fixture / stub / absent / unknown`。`fixture` 只是样例数据；`unknown` 是尚未确认，不能当成不存在；缺失数据不能用 0 代替。

对主要场景写出“请求 → 必要读取 → 处理/计划 → 展示 → 审批（如需）→ 执行 → 核验结果”的实际链路。定义失败、取消和不确定结果的去向，不把工具尝试当成执行成功。

写操作至少检查以下边界，详细机制按模式库展开：

- 身份从可信会话绑定；模型提供的实体 ID 不构成权限，来源校验也不等于授权。
- 业务规则、字段白名单、限额、资源归属和流程顺序由执行器/Backend 强制执行。
- 高风险操作采用暂存与可信审批；审批必须绑定具体变更，执行前重新校验。聊天里的“已批准”不是审批凭证。
- 写入有幂等与并发方案；发生超时不能盲目重复执行，不承诺所有动作都可回滚。

若当前缺少鉴权、可信审批或必要业务接口，MVP 降级为只读、预览或草稿，不为凑齐闭环开放真实写入。

## 5. 输出项目方案

按 [plan-template.md](references/plan-template.md) 输出。章节可合并，不适用项一句话说明，不填充泛泛的架构术语。

必须能回答：Agent 帮谁完成什么；为什么这样拆分；Claude Agent SDK 具体接在哪里、负责什么；模型如何配置和验证；工具调用什么；哪些操作受控；第一版做什么；怎样验收。未采用 SDK 时，必须给出用户明确豁免的原话及替代路线。

关键方案项附两类定位：当前项目证据，以及采用的参考模式编号 P1–P10。新增设计明确写“本项目建议”，不要伪称仓库原有能力。

对有文件写权限的工作区，默认保存为 `docs/agent-plan.md`；已有同名文件先读取，优先另存 `docs/agent-plan.proposed.md`，不要静默覆盖。若备选也存在，选择不冲突的新文件名。用户只要聊天输出或宿主不可写时，直接给完整 Markdown。

保存后仅简要报告推荐方案、MVP、关键待确认事项及文档位置。不要自动修改 `AGENTS.md`、`CLAUDE.md` 或开始实施。

## 6. 交付前检查

使用 [evaluation.md](references/evaluation.md) 的方案检查表。修正问题后再交付；未验证的兼容性和未执行的测试如实标记。

优先检查运行框架硬约束：没有用户明确豁免却不用 Claude Agent SDK，或只有 SDK 名称、实际仍自研主循环，均不通过。再检查：是否套用电商名词、滥拆 Agent、伪造已有接口、把来源门当鉴权、把围栏/Grounding 写成绝对保证、把供应商兼容声明当实测。

## 参考不可访问时

附带摘要足以完成架构级方案，不要求每次下载完整参考仓库。涉及 SDK 具体接口、版本或供应商支持范围时，核对官方文档及项目锁定版本，并区分文档声明与实测。网络不可用就注明“基于随 Skill 附带摘要，SDK/API 兼容性待核验”，继续完成可支持的设计；不能因此自动放弃 SDK。
