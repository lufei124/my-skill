# ADR-0004: 三个确认门为铁律

- 状态：已采纳
- 日期：2026-07-25
- 影响：流程铁律（难逆）

## 背景

需求工坊易在输入只是想法或模糊需求时直出 PRD。提前生成 PRD 会固化错误范围并污染后续原型与评审，且「评审已解决」与「摘要已冻结」易混淆，使陈旧摘要误导下游返工。

## 决策

三个确认门为铁律：需求理解确认门、交互原型确认门、评审争议确认门。没有通过前置确认门，就没有 PRD。门禁以 `templates.md` 第 4 节固定词表状态字段为机器可读契约，下游子 Skill 前置门禁于上游状态字段。

## 备选方案

- **可跳过门直出 PRD**：固化错误范围，污染原型与评审，返工成本高。被否。
- **单门合并**：需求与原型未分别确认即进 PRD，丢失原型可点击验证环节。被否。
- **门禁靠版本字符串/文件存在判定**：可绕过（文件存在 ≠ 内容已确认），故门禁于显式状态字段。被否。

## 后果

- 商业模式/范围/核心规则/重大技术/多方案争议不得由 Agent 决定，须给推荐+备选+取舍交用户。
- 评审确认核心规则变化且使已冻结摘要失效时，回需求发现重冻摘要后再进原型。可变规则见根 `SKILL.md`「三个强制确认门」与 `references/workflow.md`。
