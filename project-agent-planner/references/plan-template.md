## 6. 关键流程、状态与交互

### 核心流程

以真实场景描述请求、可信配置/身份解析、进入 Claude Agent SDK、调用已注册业务工具、SDK 事件回传及结果核验，包含一次失败分支。不得在 SDK 之外另写模型—工具主循环。若有写操作，再展开预览、批准、拒绝、失效、执行失败的去向；用户明确豁免时按指定框架展开。

**可选的高风险变更状态模型（本项目建议，需适配现有实现）**：

`draft → pending_approval → approved → applying → applied`

拒绝进入 `rejected`；到期或前置条件变化进入 `expired`；执行结果已知失败进入 `failed`；结果未知进入 `reconciling`。重试必须复用操作 ID、先核验结果；内容改变需重新审批。状态名不是参考仓库枚举。

### 安全与一致性

| 风险 | 触发条件 | 哪一层强制处理 | 拦截 / 恢复方式 |
|---|---|---|---|
| 提示注入、伪造 ID、越权、过期数据等实际风险 | 具体情况 | 真实位置或拟新增 | 具体响应和下一步 |

说明：可信身份、来源门与所有权校验的区别；写入限额；审批入口；幂等/并发；持久化；部分失败；日志脱敏和审计。建议阈值需标为待验证，不当成既定业务规则。

### UI / 会话 / 记忆 / 长任务（按需）

标清哪些字段来自服务端、哪些是模型生成内容；加载、空数据、失败和待审批如何展示。会话状态、业务状态、长期记忆分别存什么、以什么范围隔离。

已有异步任务则说明任务 ID、通知/查询、取消和恢复；没有异步执行能力不能承诺离线继续。未使用记忆/委托就说明暂不采用的原因。

## 7. 实施顺序与验收

下表默认按 SDK 路线填写。用户明确豁免时，改为指定框架的等效接入验证，保留相同安全要求；不需要 Agent 时不填 SDK 阶段。

| 阶段 | 变更内容与拟涉及模块 | 前置依赖 | 可验证的完成条件 |
|---|---|---|---|
| SDK / 模型接入验证 | SDK 承载与少量业务工具；仅规划验证，不自动执行 | 可用运行环境、获准的端点/模型 | 多轮工具闭环、流式、错误与取消通过；各供应商分别记录状态 |
| 第一闭环 | 最少工具与只读/草稿能力；基本隔离、限流、超时、预算和审计 | SDK 最小闭环与已识别业务依赖 | 真实读取、正确来源、无越权、超限能停止 |
| 受控操作（如需） | 审批、执行、一致性 | 权限与可信审批可用 | 拒绝/通过/重试路径正确 |
| 生产优化 | 按需求增强持久化、容量、可观测性 | 实际部署与测试数据 | 具体契约测试与回归集；不能在此阶段才首次补授权和预算 |

若已有 Agent，按风险和收益列“保留 / 改造 / 新增”，不是重新搭建全套。

输出与 MVP 对应的测试用例：前置状态、输入、预期调用/禁止调用、结果状态、通过条件。安全门用确定性测试，模型选择用行为评测。参考 [evaluation.md](evaluation.md)，只保留适用项。

效果指标覆盖任务成功率、关键事实错误、越权/误写、必要的人类接管和单任务耗时/成本。给采集口径，目标值标为建议；没有评测数据不承诺收益。
