# 配置 CSV 交付物规范

本规范定义 PRD 涉及配置表时，必须同步产出的三类配置交付物：原始 CSV 数据源、`字段说明` 文档、`csv-config-guide.md` 配置说明。其目标是让策划、客户端、服务端和测试能基于同一份机器可读配置直接工作，减少 PRD 文字描述与落地 CSV 之间的漂移。

## 适用范围

- PRD 中新增、修改或扩展配置表时触发。
- 不生成运营后台；所有运营控制通过配置表完成。
- 窄任务（只补配置表、只调数值）可单独产出本交付物，但须标记 `narrow_task`，不伪造正式 PRD 流程状态。

## 目录结构

在需求工作目录下创建：

```text
history/<日期>-<需求简称>/
├── csv/
│   └── <table_name>.csv
├── 字段说明/
│   └── <table_name>.csv 字段说明文档
├── csv-config-guide.md
└── ...（其他阶段产物）
```

- `csv/`：原始配置表 CSV，前 4 行为表头，第 5 行起为数据。
- `字段说明/`：每张表一份字段说明文档，与项目 `产品文档/字段说明` 目录的命名和描述风格保持一致。
- `csv-config-guide.md`：描述每张表的配置目标、字段概述和整个系统的配置顺序。

## CSV 文件格式

### 表头结构（固定 4 行）

| 行号 | 内容 | 说明 |
|---|---|---|
| 第 1 行 | 中文字段名 | 与界面、字段说明文档保持一致 |
| 第 2 行 | 是否需要翻译 | `0` = 不需要翻译；`1` = 需要翻译。所有描述性、名称类文字字段必须填 `1` |
| 第 3 行 | 英文字段名 | 每个单词首字母大写（PascalCase），例如 `Id`、`Name`、`StageBuffId` |
| 第 4 行 | 字段类型 | `int` / `string` / `bool` / `long` / `float` |
| 第 5 行起 | 数据 | 必要的演示数据或正式配置数据 |

### 表头示例

```csv
ID,属性名,属性类型,最小值,最大值,阶段,对应阶段BUFF,阶段名称,道具图标
0,0,0,0,0,0,0,0,0
Id,Name,Type,Min,Max,Stage,StageBuffId,StageName,AttIcon
string,int,int,int,int,string,string,string,string
1001,健康,1,0,100,25|50|75|100,0|0|10002|0|10004,危机|亚健康|健康|精力充沛,icon_health
```

### 表头规则

- 英文字段名在同一表内不得重复。
- 英文字段名使用 PascalCase：`Id`、`Name`、`MinValue`、`StageBuffId`。
- 布尔类型沿用项目既有写法（参考 `TRUE` / `FALSE`）。
- 第 2 行翻译标记仅对第 1 行中文字段生效；数值、ID、枚举值、资源路径等不需要翻译的字段填 `0`。
- 描述性字段（名称、说明、阶段名称、提示文案等）必须填 `1`。

### 数据规则

- 每张表必须包含必要的演示数据，覆盖主流程、常见状态和边界情况。
- 演示数据不是占位符，应能直接用于客户端/服务端联调或测试验收。
- ID 字段必须说明取值规则，建议按区间分段（如 `1001-1999` 基础属性、`2001-2999` 成长属性）。
- 枚举字段在数据中给出典型值，并在字段说明文档中逐值解释。
- 多值分隔符（如 `|` 分隔的阶段阈值）在字段说明文档中明确声明。

## 字段说明文档格式

文件名：`<table_name>.csv 字段说明文档`（`.csv` 与 `字段说明文档` 之间一个空格）。

### 结构

```text
<中文表名>（<N个字段>）
<配置目标：一句话说明本表作用>

<字段分组>（<N个字段>）

<中文字段名>（<EnglishName>）
- 类型：int|string|bool|long|float
- 作用：字段业务含义
- 为空时填写：0 / 不可为空
- 配置说明：
  - 枚举值与业务含义
  - 格式、单位、样例
  - ID 分段规则
  - 边界情况与异常值处理
  - 关联字段或表
```

### 字段说明要求

- 首行括号内的字段数必须与实际字段数一致；新增字段后同步更新。
- 每个字段必须包含：类型、作用、为空时填写、配置说明。
- 枚举字段逐值列出：数字值、状态名、业务含义、触发条件。
- 明确边界情况：最小值/最大值、空值、非法值、越界处理。
- 明确 ID 规则：分段区间、预留空间、新增扩展方式。
- 明确关联关系：外键引用、字段间约束、与 BUFF/奖励/事件表的联动。

### 字段说明示例

```text
attribute.csv 字段说明文档
配置目标：定义角色属性类型、数值范围及状态阶段划分。

基础信息模块（8个字段）

ID（Id）
- 类型：string
- 作用：属性的唯一标识符
- 为空时填写：不可为空
- 配置说明：
  - 1001-1999：基础生存属性（如健康、情绪）
  - 2001-2999：身体/智力属性（如体力、学识、气质）
  - 3001-3999：社会属性（如声望）
  - 9001-9999：特殊背景属性（如家境）

属性名（Name）
- 类型：string
- 作用：属性在界面显示的名称
- 为空时填写：不可为空
- 配置说明：
  - 需要翻译（csv 第 2 行标记为 1）
  - 显示给玩家的中文名称
```

## CSV 配置说明（csv-config-guide.md）

`csv-config-guide.md` 是配置系统的总览文档，用于说明配置顺序、表间依赖和关键设计决策。

### 内容结构

```markdown
# CSV 配置说明

## 1. 配置目标

- 本系统通过配置表控制哪些规则/内容。
- 与相邻系统（奖励、BUFF、NPC、任务等）的边界。

## 2. 表清单与配置顺序

| 顺序 | 表名 | 依赖表 | 配置目标 | 优先级 |
|---|---|---|---|---|
| 1 | attribute.csv | 无 | 定义属性元数据 | 必须先配 |
| 2 | buff.csv | attribute.csv | 定义属性阶段触发的 BUFF | 依赖属性表 |

## 3. 每张表的字段概述

### attribute.csv

| 字段 | 类型 | 概述 |
|---|---|---|
| Id | string | 属性唯一标识 |
| Name | string | 显示名称，需翻译 |
| Type | int | 属性大类：1 基础生存、2 成长、3 社会、9 背景 |

## 4. 系统配置顺序

1. 先配置基础元数据表（如 attribute.csv）。
2. 再配置依赖元数据的业务表（如 buff.csv）。
3. 最后配置入口/表现表（如 guide_config.csv、popup.csv）。

## 5. 边界与回滚

- 新增字段时，CSV 表头四行必须同步追加。
- 删除字段必须同步更新字段说明文档和读取方代码。
- 配置错误时的默认值和兜底表现。
```

### 写作要求

- 配置顺序必须反映真实依赖关系；被依赖的表先配。
- 每张表的“配置目标”用 1–2 句话说明，不写实现细节。
- 字段概述只列关键字段，不重复字段说明文档的完整内容。
- 必须说明系统级边界：默认值、错误配置处理、历史兼容、回滚方式。

## 与 PRD 的协作关系

- PRD 正文“接口、数据和配置”章节保留配置规则的文字契约（`R-###`、读取方、生效方式、异常处理）。
- 具体字段定义、枚举值、ID 规则、演示数据落入 `csv/` 和 `字段说明/`。
- `csv-config-guide.md` 作为配置总览，在 PRD 中通过相对路径引用，不复制到 PRD 正文。
- 配置表变更时，必须同步更新 CSV、字段说明和配置说明三处；禁止只改一处。

## 禁止事项

- 不得在 CSV 中只写表头、不写演示数据。
- 不得用横向字段说明表替代 `字段说明/` 文档。
- 不得把配置表直接当数据库表设计；配置字段与持久化数据字段必须分开。
- 不得在不同表中复用同一张表的英文字段名作为表名。
- 不得为未确认的需求或假想未来场景提前创建空配置表。
