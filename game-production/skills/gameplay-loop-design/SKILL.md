# 核心玩法与长期体验设计

主要在目标明确后、原型前调用；试玩修改及新增系统前再次调用。服从 [game-production](../../SKILL.md) 的范围、证据与授权规则。先读实际产物，不把策划文档当成实现。

## 三种模式

| 模式 | 输入 | 输出 |
|---|---|---|
| 设计 | 受众、体验、平台、已定边界、已有可复用机制 | 行为链、候选方案、最小完整片段、验证假设 |
| 诊断 | 原型/代码、玩家行为或测试记录、期待与实际差异 | 事实与根因假设、优先问题、最小修改、复测办法 |
| 变更评审 | 原有循环、新系统/广告/成长提案、权威配置 | 增量影响、经济和体验风险、兼容边界、回归任务 |

目标含糊或要求冲突时读取[目标澄清子 Skill](../game-intent-interview/SKILL.md)，只追问影响当前设计的决定。没有试玩材料时给诊断假设和待验证项，不编造玩家表现。

## 1 体验与约束

区分创作目标、玩家诉求和游戏内目标；记录受众已有技能、游玩情境、输入方式、平台、内容产能和商业模式。写一句可观察的体验目标与不可牺牲项。

按需读[专业方法](../../references/design-methods.md)。MDA 是规则—动态—体验视角，不是美术清单；不强制凑两到三种体验。故事、表现、技术与机制并行检查，不要求全部定稿后才原型。

## 2 玩家行为与后果

写清：局面与可知信息 → 玩家意图 → 行动/选择 → 成本与限制 → 系统变化 → 可感知反馈 → 对下一次行动的影响。

检查关键行动的反馈能否让玩家更新预期；建模是玩家的理解，不是研发数据建模。延迟结果也要有及时的确认与可追溯后果。

按类型选择重点：操控类先验证实际输入与响应；策略经营检查多种合理选择及机会成本；叙事/家族体验检查人物、关系和延续；创造/放松体验保留表达与欣赏，不强迫风险、失败或奖励递增。

## 3 跨时间尺度

分别设计即时反馈、完整决策、单次游玩、长期变化；时间用项目证据或标注的假设，不统一锁定 30—120 秒，不要求每轮都更难。

写清什么变强、什么变不同、玩家学到什么、人物/关系/故事如何接续。区分玩家知识与游戏保存的数值/物品/记录；没有重开结构时不强行加入跨局系统。

补上满意退出点、保存/中断边界、回来时的状态摘要及下一目标。回访理由是体验假设，不等于已产生真实回访。

长期机制若承载核心体验，就和局部操作一起做最小验证；不以“先核心后meta”为由剥离它，也不提前扩建全套长期系统。

## 4 模式选择与机制组合

按问题读取[13模式库](../../references/mode-library.md)。首次架构评审可浏览全库，日常只挑相关模式，通常比较少量差异显著的方向。对候选写适用/暂缓/不适用及原因；用户已定方向时不无端推翻。

模式是启发标签，不是新增功能清单。优先用现有机制承载；不把知识与永久数值、应急储备与风险兑现、压力调整与针对反制合并成同义词。试菜既能是玩家机制，也要与开发迭代区分。

## 5 经济与副作用

对有经济的项目列来源、消耗、转移、存量、单位、结算顺序与上限；预留/分配不等于消耗。检查零资源、极端成长、停产、不可逆损失、连点与恢复。

检查单一支配策略、选择是否只是表面差异、增长后是否有新决策、反馈是否支持因果理解。增长约束可来自边际收益、容量、维护或新机会，不强制添加负反馈或暗中削弱玩家成功。

新增系统先列“新增价值/被绕过的选择/受影响的免费路径/跨阶段后果/内容与实现成本”。商业化任务读取[持续参与与商业化](../../references/engagement-and-monetization.md)，再回到此处检查影响；不能为广告故意制造缺口。

## 6 最小验证与下一步

用[实验计划](../../templates/experiment-plan.md)选择最便宜的验证：纸面取舍、资源推演、操作场景、可点击原型、人物事件或简化代际接续。注明AI演算、工程运行与真人试玩各自能证明什么，见[测试与证据](../../references/testing-and-evidence.md)。

定义继续/修改/暂缓的观察标准，不把“更上头”作为验收，不用一次少量试玩证明留存增长。体验不成立时区分实现故障、操作负担、规则问题和目标偏差，别只加奖励。

## 返回格式与交接

按[玩法方案模板](../../templates/loop-design.md)交付：目标与依据、行为链、循环、候选及取舍、主要风险、最小原型、观察标准、待确认项。讨论用简版；进入实现才按[交接协议](../../references/planning-handoff.md)展开规则/PRD。

能回答“玩家做什么、为何愿意继续、怎样停下与接续、下一步验证什么”后，返回总控安排实现。不要重复生成总计划，不修改未授权的核心规则，不宣称理论分析等于玩家验证。
