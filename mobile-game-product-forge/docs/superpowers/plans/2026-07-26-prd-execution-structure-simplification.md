# PRD 研发执行结构精简计划

## 修改目标

把当前 20 章审计型 PRD 改为研发更容易执行的统一 7 章结构，同时保留规则、配置、数据来源、异常、验收、第三方合规等关键能力。

## 当前问题

- 同一功能信息分散在背景、目标、场景、范围、客户端、服务端、状态、异常和验收等多个章节，研发需要反复跳转。
- L2 仍需维护大量章节及裁剪说明，文档结构成本高于业务说明价值。
- 项目不使用运营后台，相关章节与实际工作方式不符；运营调整均通过配置表完成。
- “复杂流程加流程图”过于笼统，缺少图类型、触发条件和使用边界。
- 多模块需求若机械按模块拆章，AI 容易把客户端、服务端、数据库、配置和埋点拆成过细模块。

## 目标结构

统一为：

0. 文档信息
1. 功能说明
2. 总体流程
3. 功能规则
4. 页面和交互（按需）
5. 接口、数据和配置（按需）
6. 异常和边界
7. 验收标准

指标、三方对接、状态机、迁移、灰度、监控等只在触发时作为专项附录或对应章节的补充内容生成。

## 关键设计

1. “需求目标”收敛为一句“实现目标”，不默认拆用户/业务/产品目标、非目标、核心/辅助指标和成功标准。
2. 多模块仅在“涉及模块”表标影响范围；正文默认按功能流程和 R-### 规则组织。
3. 只有业务部分具备独立入口、流程、规则集合、数据生命周期或验收闭环中的至少两项时，才允许在功能规则内按业务能力分组；不得按客户端/服务端/数据库/配置/埋点拆功能模块。
4. 删除运营后台章节，所有运营控制统一进入配置表合同。
5. 细化六类图：业务流程图、页面流转图、时序图、状态机图、模块关系图、数据流图；按问题触发，不机械生成。
6. L1/L2/L3 共用同一主结构，仅改变深度和专项附录，不再维护章节裁剪决定。
7. `lint-prd.py` 同时支持新结构和历史 20 章 PRD，避免历史文档被强制迁移。

## 兼容策略

- 新生成 PRD 默认使用统一 7 章结构。
- 历史 20 章 PRD 可继续评审和校验，不要求批量迁移。
- D-### → R-### → AC-###、配置表纵向字段格式、埋点 12 列、原型双路径和阶段门禁保持不变。

## 验证方式

- `python3 scripts/lint-prd.py fixtures/valid-prd.md` 返回 0。
- `python3 scripts/lint-prd.py fixtures/invalid-prd.md` 返回 1。
- 增加规则表/验收表编号解析验证。
- `bash scripts/validate.sh`、阶段门禁自测、Python 编译、Shell 语法及 `git diff --check` 全部通过。
