# 决策：从周目容器向剧本容器迁移

## 文档状态

- 决策编号：D-SCRIPT-001
- 状态：有效（目标架构）
- 更新时间：2026-07-26
- 触发来源：[剧本选择功能](https://uvidumfqwzk.feishu.cn/wiki/LBVrwEm8tiemrAkbrsfc5lvnnwW)，抓取 revision 2012；用户确认后续游戏按该架构演进

## 决策

1. 产品向剧本制演进，剧本成为开始游戏、创角、局外养成、世界内容和后续扩展的上层容器。
2. 周目概念和相关字段逐步迁移为剧本/剧本 ID。
3. 迁移完成前，现行周目、轮回结算和历史存档继续兼容。
4. 新需求优先接入剧本结构；若继续扩展周目专属结构，必须说明原因、兼容范围和后续迁移方案。

## 取舍

- 选择剧本容器：便于多世界观、多内容包、不同创角规则和局外养成规则扩展。
- 不立即删除周目：局外养成和既有数据仍使用周目/轮回语义，直接删除会破坏历史兼容。

## 新需求影响

- 开始游戏与角色栏位必须识别剧本。
- 配置、存档、埋点、UI 文案和服务端数据需要逐步以剧本 ID 为主键或维度。
- 需求文档必须区分“现行周目机制”和“剧本化目标态”。

## 待复核

- 首个完全以剧本为权威容器的版本。
- 旧周目字段、存档和埋点维度的迁移计划。
- “灵蕴点/轮回点”的规范术语。
