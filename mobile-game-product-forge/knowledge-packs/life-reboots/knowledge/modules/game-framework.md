# 剧本与核心玩法框架

更新时间：2026-07-26  
状态：迁移中 / 目标架构  
负责人：李政融

## 1. 模块定位

本模块承载 Life Reboots 的人生主循环、剧本选择、创角路由、局外养成、事件调度和结果结算。产品正从以“周目”为主要容器的结构迁移为以“剧本”为上层容器的结构。

## 2. 稳定主循环

```text
年龄推进
→ 触发事件、剧情或主动选择
→ 骰子/规则/玩家决策
→ 属性、资源、关系和资产变化
→ 新状态影响后续事件与功能
→ 继续成长或死亡结算
```

## 3. 剧本化目标架构

- 点击开始游戏后进入剧本选择。
- 剧本配置决定是否进入创角、局外养成以及后续入局流程。
- 剧本逐步替代周目成为存档、内容、世界规则和扩展能力的上层标识。
- 旧周目字段在迁移完成前保留兼容；新需求优先使用剧本 ID，不新增只依赖周目的长期结构。
- 首次剧本、既有角色和历史存档的兼容行为必须在具体需求中单独说明。

## 4. 局外养成

- 一局正常死亡后，按年龄和总资产结算长期资源，用于后续角色的形象、初始属性和天赋。
- 中途主动重启不结算长期资源。
- 形象和天赋属于直接消耗，初始属性属于占用；返还规则必须由服务端结果决定。
- 需求原文同时使用“灵蕴点”和“轮回点”，规范名尚待复核；新文档引用时须标注来源，不能自行统一。

## 5. 事件系统

事件系统分为三层：

1. 触发与调度：按条件、优先级、冷却、最大次数和队列策略触发。
2. 客户端呈现：渲染通知型、决策型和任务型事件，处理内容降级与交互反馈。
3. 服务端结算：校验消耗、执行效果、发放奖励、更新状态并触发后续事件。

权威规则：

- 消耗、奖励和多项数值变更由服务端原子处理。
- 客户端只做体验性校验和呈现。
- 事件配置引用的选项、效果、下一事件和道具 ID 必须在加载或执行前校验。
- 结算失败不得静默丢失资产；暂存、邮箱、重试或回滚方案由具体需求明确。

## 6. 新需求检查

- 是否继续依赖周目字段，是否应改用剧本 ID。
- 是否影响创角、局外养成、首次进入、重启和历史存档。
- 是否复用现有事件类型、队列、消耗和奖励结算。
- 是否新增配置、事件埋点或服务端状态。
- 是否影响 NPC、商城、广告或任务系统。
