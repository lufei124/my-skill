# ADR-0001：grilling 对齐强制不可跳过

状态：已采纳

## 背景

深度调研最常见的失败模式是「未对齐就动手」：用户说「调研一下 X」，Agent 立即扎进源码、产出一份范围、目标、视角都含糊的报告，事后才发现与用户期望错位（用户想为重写提取机制，Agent 却在做忠实还原；用户关心商业化，Agent 却只做工程批判）。一旦大规模并行 Workflow 跑完，纠正成本极高。

## 决策

**阶段 0 Grilling 对齐是强制的，不可跳过**。进入任何资料阅读或 Workflow 之前，必须逐一向用户确认 `references/grilling-questions.md` 的决策点（范围 / 目标 / 领域预设 / 团队 / 产出结构 / stories 视角 / 保存位置 / 对抗机制 / 执行方式 / 批判视角范围 / 资料来源 / 是否 commit）。每个问题等待用户回答后再继续；用户已在初始请求中明确的点可跳过但须在总则中记录。选定领域预设后，预设文档的「追加问题」也要一并确认。

## 备选方案

- 允许 Agent 在「意图明确」时跳过 grilling：被否，意图是否明确本身就是需要对齐的，跳过即把假设当结论。
- 用一份表单让用户一次性填完：被否，连续提问能在用户答 A 后据此调整问 B（如选 game-mud 预设后才问战斗/经济侧重），表单做不到条件分支。
- 把对齐结果只存对话不落盘：被否，总则 `00-brief/brief.md` 是 Workflow 各 agent 的共享上下文，不落盘则并行 agent 各自脑补。

## 后果

- `SKILL.md` 阶段 0 标注「强制，不可跳过」；`grade_research_init.py` 的 `starts_with_grilling_or_alignment` 断言校验 brief 覆盖范围/目标/团队/方法/约束等对齐要素。
- grilling 花费的前置成本换取 Workflow 产出的一次到位，避免整轮返工。
- 领域预设的「追加问题」机制（见 [ADR-0004](0004-pluggable-domain-presets.md)）使 grilling 在不同领域可扩展而不改通用正文。
