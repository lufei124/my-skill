# 持续参与与商业化：可选分支

本文件是本包设计建议，不是平台合规清单或收益保证。先读[玩法子 Skill](../skills/gameplay-loop-design/SKILL.md)的目标和循环，再决定哪些条目适用。没有社交、配给或付费漏斗不构成设计缺陷。

## 持续参与检查

| 候选 | 要解决的问题与必要条件 | 主要风险 |
|---|---|---|
| 稀缺性与倒计时 | 选择需要真实约束或节奏吗？时间如何可读、可退出？ | 虚假紧迫、错过焦虑、限制正常生活 |
| 可变比率奖励 | 行动次数与奖励分配是否需要变化？随机来自哪里？ | 不可预测成本、用随机补偿空洞玩法；可变比率不等于所有随机掉落 |
| 社交纽带 | 合作、共同经历或关系是否服务受众？ | 单机硬塞社交、社交压力与治理成本 |
| 召回触发 | 已有明确回访价值吗？触达是否经许可？ | 打扰、把推送点击当回访体验、跨平台照抄 |
| 身份表达 | 玩家是否有可表达的偏好与被理解的对象？ | 只有属性排行、被迫参与 |
| 新鲜感 | 新内容是否带来新理解、选择、故事或表达？ | 换皮重复、产能不可持续 |
| 配给制 | 是否真的需要限制次数或资源流速？ | 人造卡点、等待取代玩法 |
| 完成欲 | 集合或阶段目标是否有清晰意义和结束点？ | 无限清单、完成后被重新清零 |
| 付费转化漏斗 | 项目是否允许内购，价值与价格能否明确理解？ | 仅广告项目强加付费、误导或重复购买 |

每项标“采用/暂缓/不适用+依据”，无固定前三优先项。Hook及心理机制只作待核验的类比或自查视角，不承诺照步骤必上瘾；以玩家自主、满意退出和可恢复为边界。

## 商业模式与分工

先选并记录：不变现 / 仅广告IAA / 仅内购 / 混合 / 已定其他模式。没有授权不替换模式。仅广告不自动加入首充、月卡、订阅或Battle Pass。

商业化专项细化点位与规则，玩法子 Skill 评审经济与体验影响，工程验证SDK、存档和生命周期，数据任务定义可观测指标。没有外部专项 Skill 时按[交接协议](planning-handoff.md)完成必要范围，不假称工具存在。

## 广告提案字段

写明玩家意图、出现位置、触发条件、普通路径、奖励来源/单位/公式/上限、资格、次数范围、重置时区、间隔、首次保护、失败处理、去重键与持久化。定义“局”究竟是会话、关卡、战斗还是重开；模拟时间不能冒充现实冷却时间。

激励视频由玩家主动选择，提前说明奖励；基础收益与额外奖励分开。不故意降低免费供给逼观看，不把每次自动行为变成弹窗。插屏只在平台允许且体验合适的自然断点评估，Banner不默认常驻。频次、奖励比例和保护时间均为待测试配置，不存在通用“每局两到三次安全线”。

工程验收需覆盖：加载失败、未完成、完整观看、重复/延迟回调、退出重进、切后台与崩溃恢复。仅以当前SDK的有效完成凭据发奖；奖励与领取记录一致保存。区分展示、完播、奖励到账，不把本地演示当生产防作弊。

有模拟时间的游戏检查广告期间暂停、恢复原速度、事件倒计时、广告耗时排除离线补算。无法可靠识别中断区间时明确缺口，不承诺永不漏发或重发。是否需要服务端验证按风险和平台能力评估，不为单机无端增加后端。

## 内购、活动与召回

仅在已选模式需要时进入。价格、价值倍数、赛季长度、召回天数依据受众、内容产能与试验确定，不固化首充三到五倍、45—60天或1/3/7/14天模板。

平台、地区、SDK、资质、隐私、未成年人、概率披露和触达权限在实施时查官方资料，记录链接、核验日期、适用条件与未决项。不把微信约束移植到TapTap，不把“有API”当准入通过；保底、随机奖励与法律要求分别核验。

## 评估与停止条件

观察无广告路径完成情况、观看选择、加载/展示/完播/到账漏斗、收益、退出、留存及资源经济。收入无法获取就标缺失，不能从完播量臆算收入。标明样本、分组、窗口和混杂因素；问题阈值与撤回条件在试验前设定。不能只因收入或留存上升就忽略可用性、人物体验或玩家自主性下降。
