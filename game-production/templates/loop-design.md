# 玩法与长期体验方案

## 范围与依据

- 模式：设计 / 诊断 / 变更评审
- 当前工程/原型/配置版本与证据：
- 关联已确认决定与禁止改变项：
- 受众、平台、输入、游玩情境、制作与商业约束：
- 一句话目标体验：
- 事实 / 假设 / 建议 / 待确认：

## 最小完整体验

起始局面与可知信息 → 玩家目标 → 行动或选择 → 代价/限制 → 系统变化 → 反馈 → 下一次行动。

- 关键取舍、操控或情感后果：
- 失败、取消、重试与恢复（不适用说明）：
- 即时反馈 / 完整决策 / 单次游玩 / 长期变化：
- 变强什么、变不同什么、理解或关系留下什么：
- 满意退出点、保存边界、回来时怎样接续：
- 经济来源、消耗、转移、单位与上限（适用时）：

## 风险与制作决定

- 最薄弱的体验假设：
- 是否存在单一支配策略、看不懂的后果、疲劳操作或经济失衡：
- 新系统/广告会绕过什么选择、影响哪个普通路径：
- 本轮最小原型内容、明确不做的内容：
- 观察标准、继续/修改/暂缓条件：
- 交给策划、UI、工程、数据和测试的必要任务：

详细实验使用[实验计划](experiment-plan.md)，不要用完整GDD替代这一轮的决定。
