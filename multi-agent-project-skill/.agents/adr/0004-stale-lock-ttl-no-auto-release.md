# ADR-0004：陈旧锁 TTL 仅触发检视，不自动释放

状态：已采纳

## 背景

`.agent/FILE_LOCKS.md` 的 ACTIVE 锁可能因原 Agent 会话中断、忘记释放而长期挂着，阻塞其他 Agent。需要判定何时可视为「陈旧」并接管。但「永不擦除、重置、重新格式化或覆盖其他 Agent 未合并的成果」是不可妥协规则；自动释放锁可能让接管者覆盖原 Agent 未提交的工作。

## 决策

ACTIVE 锁的 `Last updated` 距今超过 **4 小时**可被任何 Agent**提请检视**，但标记 `STALE` 仍须满足三者之一：原分支无进行中迹象、原 Agent 在注册表标记不可达、协调者或用户授权接管。TTL **只是触发检视的信号，不自动释放锁**。接管走独立的接管协议（标记旧锁 `STALE` 不删历史、记录 takeover reason、从已校验状态继续）。

## 备选方案

- TTL 到期自动释放锁：被否，违背「永不擦除他人成果」原则，可能覆盖未提交工作。
- 不设 TTL，全靠人工发现：被否，长时间挂起的锁难以及时发现，协作停滞。
- TTL 设为更短（如 30 分钟）：被否，正常长任务（构建、大重构）会被误判，频繁打断。

## 后果

- 陈旧锁可被发现但不会被静默释放；接管有据可查。
- 4 小时阈值是经验值，可由项目在 `DEVELOPMENT_RULES.md` 调整，但「不自动释放」是硬约束不可改。
- ACTIVE 锁须随每次检查点刷新 `Last updated`，连续工作超 60 分钟也须刷新，避免被误判陈旧。
