# 测试与证据

本文件是本包验证协议。理论分析提出假设，工程测试检查实现，真人试玩观察体验，业务数据观察实际行为；它们不能互相代替。

## 证据阶梯

| 已完成的工作 | 能支持 | 不能直接支持 |
|---|---|---|
| 文件/代码审查 | 已见实现和潜在问题 | 已跑通或玩家喜欢 |
| 脚本/账本模拟 | 指定输入下规则、单位和边界 | 真人策略分布、乐趣或留存 |
| 浏览器/引擎运行 | 对应环境中的路径与输出 | 目标真机、真实广告或其他平台兼容 |
| 目标设备操作 | 已测试设备的运行与交互 | 所有机型或所有玩家 |
| 少量真人试玩 | 可理解性、行为线索与方向问题 | 稳定的留存/收入增幅 |
| 实际回访与实验 | 明确样本和口径内的观察结果 | 无条件归因或对其他人群泛化 |

## 最小实验

用[实验模板](../templates/experiment-plan.md)先定义：假设、参与者或模拟输入、版本、任务、观察、判定、停止条件与失败后动作。一次重点验证一个关键不确定性；必须同时修改多个因素时注明无法单独归因。

纸面可以检查选择和信息，引擎小场景检查操控，人物事件或简化继任检查延续。不可为了最小化而去掉承载核心体验的部分。

给真人中性任务，先观察再追问。记录看到/做了/想达到/后果，区分操作失败、理解失败、规则无趣和目标不匹配。问题用“你刚才想做什么”，不问“是不是这个更有感情”。匿名记录必要信息，不把私人访谈上传到公共资料库。

每轮写继续/修改/暂缓及原因。测试次数、模式数量、代码通过率都不是乐趣分数；不能为过关换指标或隐藏失败。

## 留存和因果

先定义入组事件、有效用户、回访事件、自然日或滚动窗口、时区、分母、成熟观察窗口、样本量、渠道、版本和实验分组。不同口径分别展示，不把自然日与24小时留存混比，不把未到观察期的用户算流失。

自己的同口径前后对比仍可能受获客、版本、节假日、设备与用户结构变化影响。能做随机对照时记录分配、曝光和分析单位；不能时明确观察性比较与混杂因素。样本不足就保留不确定性，不许宣称次留提升必然由这次改动造成。

口头“愿意再来”不等于实际回访；完成一段有意义的有限体验也不自动是留存失败。目标与指标必须匹配。

## 工程与奖励回归

覆盖适用的正常、取消、失败、重复提交、存读、后台和恢复。广告奖励验证基础/追加分离、完成凭据、去重、持久化、次数及时间口径；没有正式平台环境时只能报告模拟通过。

## Skill本身的回归

[场景库](../tests/scenarios.json)记录目标行为测试用例。结构校验器仅检查文件、引用、字段和约束是否存在；校验器单元测试只证明坏包能被拒绝。实际LLM回归需在目标宿主逐项执行并保存模型、环境、输出、人工判定和失败复现，不把静态关键词命中当语义遵循。
