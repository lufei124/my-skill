# ADR-0003：任务 ID 用 mkdir 原子分配

状态：已采纳

## 背景

多个 Agent 并发认领任务时，若都读 `.agent/TASK_BOARD.md` 取最大编号 N 再各写 `TASK-(N+1)`，会撞号、互相覆盖看板行。需要一个无协调者进程的互斥取号机制。

## 决策

任务 ID 通过文件系统原子操作分配：候选 `TASK-(N+1)`，执行 `mkdir .agent/task-ids/TASK-(N+1)`（POSIX `mkdir` 是原子的），目录已存在则编号 +1 重试，直到成功。占位成功后**立即**在 `TASK_BOARD.md` 写完整任务行，再动工。占位目录 `.agent/task-ids/TASK-NNN` **永不删除**，作为已用编号的持久记录。

## 备选方案

- 协调者进程集中发号：被否，单点、需常驻、违背「无协调者也能安全并发」。
- 文件锁 + 读改写：被否，竞态窗口难消除，且崩溃后锁残留。
- 数据库/外部服务：被否，引入运行时依赖，违背「仓库即事实来源」。

## 后果

- 无协调者也能安全并发取号；撞号时后到者自动换号，不覆盖先到者的看板行。
- `task-ids/` 目录只增不删，编号单调；历史可追溯。
- 取号与写看板之间仍有窗口，但占位目录已是「认领意图」的持久证据，看板行缺失时可据此补登。
