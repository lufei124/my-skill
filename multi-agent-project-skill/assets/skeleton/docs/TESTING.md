## 按任务规模选验证范围

- **小任务**：运行最小相关测试，并至少检查 diff。
- **中型任务**：运行相关测试、lint、构建；跨模块时运行集成或冒烟检查。
- **大型任务**：建立阶段性基线，最终运行完整验证（`{{TEST_COMMAND}}` + 构建 + lint），必要时增加数据回滚或部署验证。

## 失败分类与处理

失败原因区分：环境 / 依赖 / 测试本身 / 代码 / 配置 / 文档漂移。

- 不得通过删除断言、跳过测试或静默 fallback 造绿。
- 若失败与本任务无关，记录证据、说明是否为基线问题并保持本任务范围。
- Warning 区分存量与新增，不把存量 warning 当新代码免检。
- 人工验证步骤必须可复现。
