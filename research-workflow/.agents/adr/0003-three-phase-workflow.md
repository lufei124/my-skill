# ADR-0003：三阶段 Workflow：并行初稿 -> 红队 -> 评审委员会

状态：已采纳

## 背景

调研既要覆盖广（一手资料、抽象方案、外部批判多视角并行），又要可信（结论须经对抗检验而非单线产出），还要收敛（多视角初稿须有人统一文风、裁决分歧、消除矛盾）。单线串行写作既慢又容易陷入单一视角的盲区；一次性全并行又会让矛盾结论并存、无人收口。

## 决策

调研执行采用**三阶段 Workflow**（脚本模板见 `references/workflow-template.md`）：**Phase 1 并行初稿**（资料考古组 / 抽象与方案组 / 批判性外部视角组并行产出各自章节）；**Phase 2 红队对抗**（横向对比验证、现代实践挑战、体验风险挑战、价值风险挑战，对初稿与抽象方案尖锐质疑）；**Phase 3 评审委员会汇总**（审阅全部初稿与红队报告，统一文风、消除矛盾、裁决分歧、生成最终报告）。Workflow 完成后检查失败 agent 并补全（阶段 3），最终检查与汇报（阶段 4）。

## 备选方案

- 单线串行：被否，慢、单视角盲区、无法在期限内并行压榨。
- 全并行无收口：被否，矛盾结论并存，最终报告无人对齐。
- 两阶段（初稿 + 汇总，无红队）：被否，缺对抗检验，抽象方案与既有机制的风险无人挑战，可信度不足。
- 把红队并入评审委员会：被否，红队的职责是「主动找茬质疑」，评审委员会的职责是「裁决收口」，职责混同会让委员会既当运动员又当裁判。

## 后果

- `grade_research_init.py` 的 `proposes_multi_agent_workflow` 断言校验 brief 提到 Workflow / 多 Agent / 红队 / 评审委员会。
- Workflow 模板分三阶段，每阶段输入依赖上一阶段产出，pipeline 结构天然表达该依赖。
- 阶段 3「补全失败产出」明确：单个 agent 失败不丢弃整轮，单独重跑该角色，最终报告引用补全文件。
- 红队的具体视角范围由 grilling 决定（见 [ADR-0001](0001-grilling-first-mandatory.md)），不硬编码在通用正文。
